Every CKB cell carries a lock script and, optionally, a type script. Cellora recognizes well-known scripts and tags them, so you can identify what a cell is without maintaining a table of code hashes yourself.

## Recognized scripts

Cellora tags these well-known lock and type scripts:

<CardGroup cols={2}>
  <Card title="sighash" icon="signature">
    The default single-signature lock (`secp256k1_blake160_sighash_all`). Tagged as a lock script.
  </Card>
  <Card title="multisig" icon="users">
    The `secp256k1_blake160_multisig_all` lock. Tagged as a lock script.
  </Card>
  <Card title="nervos_dao" icon="piggy-bank">
    The Nervos DAO deposit/withdraw script. Only ever a type script.
  </Card>
</CardGroup>

The registry currently covers these entries on both **mainnet** and **testnet**. Additional well-known scripts (for example xUDT, Spore, Omnilock, or RGB++) are added over time; scripts that are not in the registry are simply left untagged.

## How tags appear

A recognized cell carries a `lock_kind` for its lock script and, where applicable, a `type_kind` for its type script. The value is the stable label — `sighash`, `multisig`, or `nervos_dao`. Unrecognized scripts omit the corresponding kind entirely — you still get the full `lock` / `type` script objects (`code_hash`, `hash_type`, `args`) to inspect yourself.

The raw script objects are always present:

```json
{
  "lock": {
    "code_hash": "0x9bd7e06f3ecf4be0f2fcd2188b23f1b9fcc88e5d4b65a8637b17723bbda3cce8",
    "hash_type": "type",
    "args": "0xdeadbeef"
  },
  "lock_hash": "0xabc...",
  "lock_kind": "sighash"
}
```

## Why it helps

Instead of decoding code hashes to figure out whether a cell is a default sighash lock, a multisig lock, or a Nervos DAO cell, you can filter and branch on the tagged kind. Specificity like this is CKB-native: you work with what a cell is, not just with an opaque hash.

Cells are returned by [`GET /v1/cells`](/rest/cells) and the [GraphQL `cells` query](/graphql/queries).
