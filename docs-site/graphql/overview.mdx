`POST /graphql` exposes the same data as the [REST surface](/rest/overview) through a single typed query root.

## Authentication

Identical to REST: send your key as a Bearer token in the `Authorization` header. See [Authentication](/authentication).

## Rate limiting

The GraphQL rate-limit bucket is **separate** from REST, so the two surfaces do not consume each other's quota. See [Rate limiting](/rate-limiting).

## Quick example

```bash
curl -s -X POST $CELLORA_BASE/graphql \
  -H "Authorization: Bearer $CELLORA_KEY" \
  -H "Content-Type: application/json" \
  -d '{"query":"{ blocksLatest { number hash transactionsCount } stats { lagBlocks isStale } }"}' | jq
```

## Errors

GraphQL uses the standard GraphQL response shape — a top-level `errors` array on a `200` response:

```json
{ "data": null, "errors": [{ "message": "..." }] }
```

<Warning>
Branch on the response shape, not the HTTP status. Auth failures and rate-limit refusals still return `401` / `429` with the REST error envelope, because those checks run before the GraphQL handler. See [Error handling](/errors).
</Warning>
