---
title: "Rate limiting"
description: "Per-key token buckets with separate REST and GraphQL limits, X-RateLimit headers, and 429 handling with Retry-After."
---

Limits are enforced per API key using a token bucket. REST and GraphQL have independent buckets, so the two surfaces do not consume each other's quota.

## Tier limits

Default limits, sized for sanity and tuneable via environment variables:

| Tier | REST burst | REST refill | GraphQL burst | GraphQL refill |
| --- | ---: | ---: | ---: | ---: |
| `free` | 30 | 1 / sec | 10 | 0.5 / sec |
| `starter` | 300 | 20 / sec | 100 | 10 / sec |
| `pro` | 3,000 | 200 / sec | 1,000 | 100 / sec |

<Info>
During the alpha, tiers are rate-limit presets only — there is no billing, and every tier is freely available. Pick the tier whose limits suit your workload.
</Info>

## Response headers

| Header | Present on | Value |
| --- | --- | --- |
| `X-RateLimit-Limit` | 2xx, 429 | Bucket capacity for this key and surface. |
| `X-RateLimit-Remaining` | 2xx, 429 | Tokens remaining after this request. |
| `X-RateLimit-Reset` | 2xx, 429 | Seconds until the bucket refills to full from its current state. |
| `Retry-After` | 429 only | Seconds to wait before retrying. |

## Handling 429

When a bucket is empty, the request returns `429 rate_limited` with `Retry-After` set to the seconds until a token is available.

```bash
resp=$(curl -s -w "\n%{http_code}" -D /tmp/h \
  -H "Authorization: Bearer $CELLORA_KEY" \
  "$CELLORA_BASE/v1/blocks/latest")

if [ "$(echo "$resp" | tail -1)" = "429" ]; then
  wait=$(grep -i '^retry-after:' /tmp/h | awk '{print $2}' | tr -d '\r')
  sleep "$wait"
fi
```

<Tip>
For production workloads, implement exponential backoff with jitter rather than a fixed delay, and always honor `Retry-After` when present.
</Tip>

## Failure behavior

When the backing store (Redis) is unreachable, the limiter fails open by default, so a limiter outage does not take down reads. Set `CELLORA_API_RATE_LIMIT_FAIL_OPEN=false` to fail closed instead.
