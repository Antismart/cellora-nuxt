---
title: "Health and readiness"
description: "GET /v1/health is the liveness probe; GET /v1/health/ready is the readiness probe. Neither requires auth."
---

Two probe endpoints for container orchestrators. Both are public — no API key required.

## GET /v1/health

Liveness probe. Always returns `200` if the process is running.

```bash
curl -s $CELLORA_BASE/v1/health | jq
```

```json
{ "status": "ok", "version": "0.1.0" }
```

## GET /v1/health/ready

Readiness probe. Each configured dependency is probed concurrently with a 1-second timeout. Returns `200` when every required dependency answered and `503` when any of them errored. `status` is `"ready"` on `200` and `"not_ready"` on `503`.

```bash
curl -s $CELLORA_BASE/v1/health/ready | jq
```

```json
{
  "status": "ready",
  "db": "ok",
  "redis": "ok",
  "ckb_node": {
    "state": "ok",
    "tip": 14823420,
    "is_synced": true
  }
}
```

## Fields

| Field | Type | Notes |
| --- | --- | --- |
| `status` | string | `"ready"` when every required dependency answered, `"not_ready"` otherwise. |
| `db` | string | Postgres pool state — `"ok"` or `"error"`. |
| `redis` | string | Redis state — `"ok"`, `"error"`, or `"skipped"` when no Redis client was attached at startup. |
| `ckb_node` | object | CKB node probe result (see below). |
| `ckb_node.state` | string | `"ok"`, `"error"`, or `"skipped"` when no CKB client was attached. |
| `ckb_node.tip` | integer \| null | Tip height the node reported, when reachable. |
| `ckb_node.is_synced` | boolean | `false` when the node is in initial block download (this does **not** flip the response to `503`). |

<Info>
Use `/v1/health` for liveness and `/v1/health/ready` for readiness. A dependency reported as `"skipped"` is not counted against readiness — that dependency was not configured at startup. A CKB node still in initial block download reports `is_synced: false` inside a `200` response rather than a `503`, so the API can come online during catch-up. For indexer freshness rather than process health, see [`/v1/stats`](/rest/stats).
</Info>
